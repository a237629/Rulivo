# 第 34 步验收：证据报告页面

## 范围

本步只实现证据报告的数据组合接口、移动端页面和导航入口，不实现第 35 步 AI 纠错。

## 报告结构

每种行为模式展示：

- 结论：来自第 33 步已通过 JSON Schema 与证据校验的 AI 解释。
- 样本：总样本、已知样本、通过、失败、未知及反例数量。
- 影响：效应量、数据完整性、置信度分数、等级和主导状态。
- 时间窗：当前有效证据所关联交易的最早和最晚开仓时间。
- 相关交易：按开仓时间倒序展示最近二十条，并可进入交易详情。
- 反例：与当前主导状态相反的交易证据。
- 限制：AI 明示限制，加上样本不足、数据不完整和列表截断等确定性限制。

所有报告数字来自 `behavior_pattern_confidences`，交易列表来自
`behavior_evidence_snapshots` 当前有效快照。页面不重新计算指标。

## API

`GET /analytics/evidence-report`

- 必须携带 Access Token，只读取当前用户数据。
- 要求存在与当前指标 ID 一致的第 33 步解释；旧解释或缺失解释返回未找到。
- 返回每项指标的证据 ID，以及每笔相关交易对应的证据快照 ID。

## 移动端

- 证据页新增“证据报告”入口。
- `/evidence-report` 是受登录和新手引导保护的页面。
- 页面覆盖加载、未接入令牌、接口失败、无时间窗、无交易和无反例状态。
- 中英文文案完整，相关交易可进入 `/trades/[tradeId]`。

当前移动端登录页仍沿用既有认证接入状态；`SessionProvider.signIn(accessToken)` 已支持真实登录
流程传入 Access Token。没有令牌时页面明确显示接入提示，不会展示模拟私有数据。

## 数据库评估

本步不新增迁移。第 30 步快照、第 32 步置信指标和第 33 步解释记录已包含报告所需的
证据关系、版本和时间信息；新增冗余报告表会带来过期数据风险。

## 自动化验收

- API 纯函数测试覆盖七个报告区块、反例识别、时间窗、样本不足和空证据。
- 移动端客户端测试覆盖认证请求和响应契约。
- 导航测试覆盖证据报告受保护路由。
- OpenAPI 测试覆盖证据报告接口。
- 执行 API、移动端、国际化测试及全仓 lint、typecheck、build、format 检查。
